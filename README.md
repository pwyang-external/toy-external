# 사내 상품권 QR 발급/검증 도구

서버·앱 없이, 서명(HMAC-SHA256) 기반으로 상품권 QR코드의 진위를 확인하는 도구입니다.
**위조 여부만은 완전히 오프라인**으로 확인되고, 금액·유효기간·사용여부는 GitHub의 발급대장(vouchers.json)을
조회해야 알 수 있습니다 (아래 "코드 형식" 참고).

## 구성
- `issue.html` — 상품권 코드 발급 + QR 이미지 생성 (관리자가 PC에서 1회 실행)
- `verify.html` — 상품권 진위 확인 (검증자가 스마트폰에서 사용)
- `github-sync.js` — GitHub API로 `vouchers.json`을 읽고/쓰는 공통 로직
- `qrcode-lib.js` — QR 이미지 생성 라이브러리 (타사 오픈소스, 아래 "third-party" 참고)
- `github-config.local.example.js` — GitHub 설정 템플릿 (커밋됨, 토큰 없음)
- `github-config.local.js` — 실제 GitHub 설정/토큰, 평문 (⚠️ `.gitignore`에 등록되어 커밋되지 않음, 이 파일이 있는 그 컴퓨터에서만 동작)
- `crypto-config.js` — 설정을 암호(패스프레이즈)로 암호화/복호화하는 공통 로직
- `make-config.html` — 관리자가 최초 1회 실행해 `github-config.encrypted.json`을 암호화하고 GitHub에 바로 업로드하는 도구
- `github-config.encrypted.json` — 암호화된 GitHub 설정 (커밋해도 안전, 어느 기기에서든 암호만 알면 사용 가능)

## 사용 절차

### 1. 발급 (관리자, PC)
> ⚠️ **GitHub 연동이 안 되어 있으면 발급 자체가 되지 않습니다.** 코드는 `vouchers.json`에 기록되어야만
> verify.html에서 확인 가능하므로, "발급됐는데 대장엔 없는" 상황을 애초에 막기 위한 설계입니다.

1. `issue.html`을 엽니다. (make-config.html로 GitHub 설정을 먼저 만들어뒀어야 합니다.)
2. 비밀키 · 금액 · 유효기간 · 발급 수량을 입력하고 [코드 발급하기] 클릭.
   - GitHub 연동이 안 되어 있으면(비밀키가 다르거나 설정 파일이 없거나) 바로 알림이 뜨고 발급이 중단됩니다.
   - 연동이 확인되면: 과거 발급 이력과 겹치지 않는 일련번호로 코드를 만들고, **생성과 동시에 자동으로 GitHub에 저장**합니다.
3. 코드마다 QR 이미지가 표에 바로 나타납니다. 다음 중 편한 방식으로 확보하세요:
   - 표의 각 행 [PNG 저장] 링크로 하나씩 다운로드
   - [🖨️ 전체 QR 인쇄용 시트 열기] — 모든 QR을 카드 형태로 모아 인쇄(또는 PDF로 저장) 미리보기가 새 창으로 뜸
4. 자동 저장이 네트워크 문제 등으로 실패했다면 [GitHub에 발급 기록 다시 저장] 버튼으로 재시도할 수 있습니다.
5. **비밀키는 절대 이 파일에 저장되지 않습니다.** 별도의 안전한 곳(비밀번호 관리자 등)에 기록해두세요. 이 값을 잃으면 검증이 불가능합니다.

### 발급대장 정리 (사용완료/만료 후 1년 지난 코드 삭제)
`issue.html`의 **"🧹 발급대장 정리"** 버튼으로 `vouchers.json`을 계속 가볍게 유지할 수 있습니다.
- 삭제 대상: **사용완료된 지 1년이 넘게 지난 코드** 또는 **유효기간이 1년 넘게 지난 코드** (둘 중 하나만 해당해도 삭제)
  - 사용했다고 바로 지우는 게 아니라, 조회/확인용으로 **사용 후 1년간은 남겨두고** 그 뒤에 정리합니다
- 실행하면 몇 건이 삭제되고 몇 건이 남는지 먼저 보여주고, 확인해야 실제로 삭제됩니다
- **삭제된 코드는 verify.html에서 더 이상 확인할 수 없고, 되돌릴 수 없습니다** — 신중하게 사용하세요

### 2. 검증 (사용처, 스마트폰)
1. `verify.html` 파일을 스마트폰에 저장 (카카오톡/메일로 전송 후 다운로드)해두고, 필요할 때 파일 앱에서 열어 브라우저로 실행합니다.
2. 손님이 제시한 QR코드를 폰 기본 카메라 앱으로 스캔 → 인식된 텍스트를 복사.
3. `verify.html`에 비밀키와 코드를 입력하고 [확인하기] 클릭.
4. 화면에 다음 중 하나가 표시됩니다:
   - ✅ **정상** — 서명이 일치하고, GitHub 발급대장 기준으로 유효기간 이내·미사용
   - ⏰ **만료** — GitHub 발급대장 기준으로 유효기간이 지남
   - ❌ **위조/오류** — 서명이 일치하지 않거나, 서명은 맞지만 발급대장에 없는 코드
   - ⚠️ **이미 사용됨** — GitHub 발급대장(또는 GitHub 미설정 시 이 기기 로컬 기록) 기준으로 이미 사용 처리됨
   - ⚠️ **금액/유효기간 확인 불가** — 서명은 정상이지만 GitHub 조회가 안 돼서(네트워크 문제 등) 세부 정보를 못 가져온 경우

## 코드 형식
```
일련번호(4자리) + 서명(4자리) = 총 8자리, 구분자 없음
예: A1B2F9C3
```
서명은 `HMAC-SHA256(비밀키, 일련번호)`의 앞 4자리(hex)입니다. 손으로 타이핑하기 쉽도록 총 8자리로 짧게 잡았고,
**금액·만료일은 코드 안에 들어있지 않습니다** — 발급 시 GitHub의 `vouchers.json`에 함께 기록해두고, 검증 시
그 파일에서 조회합니다. 그래서 이제 "위조 여부"만 오프라인으로 확인되고, 금액·유효기간·사용여부 확인에는
인터넷 연결(GitHub 조회)이 필요합니다.

⚠️ **알아둘 점**: 일련번호가 4자리라 조합이 약 100만 개뿐이라, 발급 시 **GitHub 발급대장(vouchers.json)을
먼저 조회해서 과거에 이미 나온 일련번호와 겹치지 않는지 확인**합니다 (GitHub 연동이 안 돼 있으면 이번
배치 안에서만 중복을 피합니다). 그래도 조합 자체가 넓지 않으므로, 수십만 건 이상 누적 발급할 계획이면
일련번호 자릿수를 늘리는 걸 권장합니다 (원하시면 조정해드립니다).

## QR/카메라 없이 텍스트로만 확인하기 (사내 카메라 보안 정책 등)
QR은 이 코드 문자열을 카메라로 편하게 읽기 위한 껍데기일 뿐, 실제 검증에 쓰이는 건 처음부터 이 텍스트 코드입니다.
QR/카메라를 아예 안 쓰고 다음처럼 운영해도 완전히 동일하게 동작합니다:
1. `issue.html`에서 QR 대신 [코드만 복사] 또는 CSV로 텍스트 코드만 추출
2. 종이 인쇄 또는 사내 메신저/이메일로 코드 전달
3. 검증자는 `verify.html`의 코드 입력창에 손으로 직접 입력(또는 복사/붙여넣기)
4. 서명 검증, GitHub 사용여부 확인 등 나머지는 QR을 쓸 때와 완전히 동일하게 동작

## GitHub 연동 (필수에 가까움 — 금액/유효기간/사용여부 확인용)

코드 자체에는 일련번호와 서명만 있고 금액·만료일이 없기 때문에, GitHub 연동 없이는 위조 여부 말고는
아무것도 확인할 수 없습니다. `vouchers.json`을 GitHub 저장소에 두고 API로 읽고/고치도록 연동해야
실질적으로 쓸 수 있는 검증 도구가 됩니다.

### 설정 방법
1. 이 저장소(vouchers.json 포함)를 GitHub에 올립니다.
2. **Fine-grained PAT** 발급: https://github.com/settings/personal-access-tokens/new
   - Repository access: **이 저장소만 선택** (다른 저장소는 절대 포함하지 마세요)
   - Permissions: **Contents → Read and write** 만 부여 (그 외 전부 No access)
3. `make-config.html`을 열어 owner/repo/branch/path/token과 **암호(패스프레이즈)**를 입력하고
   [🚀 GitHub에 바로 업로드] 클릭 → 같은 토큰으로 `github-config.encrypted.json`이 저장소에 바로 커밋됩니다
   (별도로 다운로드해서 직접 올릴 필요 없음. 암호 없이는 내용을 알 수 없어 커밋해도 안전합니다).
   업로드가 안 되는 환경이라면 [💾 PC에 파일로만 다운로드]로 받아서 수동으로 커밋해도 됩니다.
4. **이때 정하는 암호를, 상품권 발급용 "비밀키"와 똑같이 맞추세요.** 그러면 다음 단계에서 입력값이 하나로 통일됩니다.

### issue.html / verify.html 둘 다 — GitHub owner/repo/branch/경로/토큰 입력칸이 아예 없음
두 파일 모두 GitHub 관련 입력창을 화면에 두지 않습니다. **오직 `make-config.html`에서 만든 설정 파일에서만**
그 값들을 가져옵니다. 사람이 하는 입력은 [비밀키] 하나뿐입니다.

`issue.html`에서 [비밀키]를 입력하고 [코드 발급하기]를 누르는 순간, `verify.html`에서 [비밀키]를 입력하고
[확인하기]를 누르는 순간, 그 값으로 다음 두 가지가 동시에 처리됩니다:
1. 상품권 서명(위조) 검증 / 발급
2. `github-config.encrypted.json` 복호화 (성공하면 그 브라우저에 자동 캐시되어 이후엔 다시 시도 안 함)

암호(=비밀키)가 서로 다르면 GitHub 연동만 조용히 실패하고, 서명 검증/발급 자체는 정상 진행됩니다 — 화면에 "오프라인 모드"로 표시됩니다.
이 경우 GitHub 연동을 쓰려면 `make-config.html`을 다시 열어서, 서명용 비밀키와 같은 암호로 설정 파일을 다시 만들어야 합니다
(수동으로 owner/repo/token을 입력하는 화면 자체가 없으므로, 고치는 방법은 오직 이것뿐입니다).

발급 후 [GitHub에 발급 기록 저장]을 클릭하면 `vouchers.json`에 발급 목록이 커밋되고, 각 검증 기기는
자동으로 GitHub을 조회해서 "이미 사용됨" 여부를 판단하고 [사용 처리]도 GitHub에 바로 반영합니다.

> 참고: `issue.html`은 관리자 PC 한 대에서만 쓴다면, `github-config.local.example.js`를 복사한
> `github-config.local.js`(평문, `.gitignore`로 커밋 차단됨)에 값을 직접 넣어두는 방법도 여전히 됩니다.
> 이 경우 비밀키 입력 없이도 항상 자동으로 채워집니다 — 단, 그 컴퓨터에서만 동작합니다.

### QR을 찍으면 검증 페이지로 바로 연결하기 (선택)
`issue.html`의 **"검증 페이지 URL"**란에는 기본값으로 `https://pwyang-external.github.io/toy-external/verify.html`이
미리 입력되어 있습니다. 다른 저장소/계정을 쓴다면 이 값을 실제 배포 주소로 바꾸면 되고, 그대로 두면 QR에는
`그URL?code=코드` 형태의 링크가 담깁니다.

효과:
- 손님/검증자가 QR을 스마트폰 **카메라로 찍으면 바로 verify.html이 열리고, 코드 입력창이 자동으로 채워집니다** (직접 복사/붙여넣기 불필요).
- 검증자가 [비밀키]를 한 번 입력해 [확인하기]를 누르면, 그 비밀키가 이 기기에 기억되어 **다음 QR부터는 스캔하자마자 결과까지 자동으로 뜹니다** (코드+비밀키가 둘 다 채워지면 자동 실행).
- "이 기기에 저장된 비밀키 지우기" 버튼으로 언제든 이 캐시를 지울 수 있습니다.

이 URL 입력란은 이 컴퓨터의 localStorage에 저장되어 다음 발급 때도 자동으로 채워집니다.

### 동작 방식
- 서명(위조) 검증 자체는 여전히 완전 오프라인입니다 — "발급되지 않은/변조된 코드"는 인터넷 없이도 걸러집니다.
- 하지만 **금액·유효기간·사용 여부는 코드 안에 없고 GitHub 발급대장에서만 알 수 있어서, 그 순간엔 인터넷 연결이 필요**합니다.
- 네트워크가 안 되거나 GitHub 설정을 안 했다면, "서명은 정상이나 세부 정보를 확인할 수 없음" 상태로 표시되고,
  그래도 [사용 처리]는 이 기기 로컬 기록으로만 대체 가능합니다 (금액/만료일 확인 없이).
- 두 기기가 거의 동시에 같은 코드를 사용 처리하면, 나중 요청은 "다른 기기에서 방금 먼저 사용 처리했습니다" 오류로 안전하게 막힙니다 (GitHub 파일의 sha 값으로 충돌 감지).

## 알아둘 점 (한계)
- **비밀키가 곧 보안의 전부입니다.** 비밀키를 아는 사람은 코드를 위조할 수 있으므로, 검증 담당자에게만 구두/별도 채널로 전달하세요. (verify.html 파일 자체에는 비밀키가 들어있지 않습니다 — 매번 입력해야 합니다.)
- **암호화된 파일을 쓰더라도, 암호를 입력해서 복호화한 순간엔 토큰이 그 브라우저 메모리에 평문으로 존재합니다.** 즉 암호화는 "git 저장소에 평문으로 남는 것"만 막아줄 뿐, 그 암호를 아는 사람이 실제로 페이지를 열어 복호화하면 이후엔 원래 토큰과 동일한 노출 위험이 생깁니다. 암호는 토큰만큼 중요하게 취급하세요.
- **GitHub 토큰은 브라우저에 노출됩니다.** 개발자도구로 페이지를 열면 누구나 토큰을 볼 수 있어, 이론적으로는 `vouchers.json`을 마음대로 고칠 수 있습니다. 그래서 반드시 **이 저장소 하나에만, Contents 권한만** 준 Fine-grained PAT를 쓰세요 — 유출되어도 피해 범위가 이 장난감 저장소로 한정됩니다. 진짜 보안이 필요한 용도라면 토큰을 서버(예: Cloudflare Worker)에 숨기는 구조로 바꿔야 합니다.
- GitHub 연동 없이 로컬 모드로만 쓰는 경우, "중복 사용 방지"는 기기별로만 동작합니다 (기존 한계와 동일).
- **verify.html은 한 번 입력한 비밀키를 그 기기의 localStorage에 기억해서 다음부터 자동으로 채웁니다.** 검증 기기를 잃어버리거나 다른 사람과 공유한다면 "이 기기에 저장된 비밀키 지우기"로 반드시 삭제하세요.
- 더 강한 보안(키 유출 시에도 위조 방지)이 필요하면 HMAC 대신 비대칭 서명(Ed25519 등)으로 바꿀 수 있습니다 — 필요하면 요청하세요.
