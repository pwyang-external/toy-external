# 사내 상품권 QR 발급/검증 도구

서버·앱 없이, 서명(HMAC-SHA256) 기반으로 상품권 QR코드의 진위를 오프라인으로 확인하는 도구입니다.

## 구성
- `issue.html` — 상품권 코드 발급 (관리자가 PC에서 1회 실행)
- `verify.html` — 상품권 진위 확인 (검증자가 스마트폰에서 사용)

## 사용 절차

### 1. 발급 (관리자, PC)
1. `issue.html`을 더블클릭해서 브라우저로 엽니다 (인터넷 불필요).
2. 비밀키 · 금액 · 유효기간 · 발급 수량을 입력하고 [코드 발급하기] 클릭.
3. 생성된 코드 목록을 CSV로 다운로드하거나 텍스트로 복사합니다.
4. **비밀키는 절대 이 파일에 저장되지 않습니다.** 별도의 안전한 곳(비밀번호 관리자 등)에 기록해두세요. 이 값을 잃으면 검증이 불가능합니다.

### 2. QR 이미지로 변환
- 발급된 코드는 순수 텍스트일 뿐, 아직 QR 이미지가 아닙니다.
- 인터넷이 되는 PC에서 무료 QR 일괄생성 도구(검색: "bulk qr code generator", 또는
  https://github.com/lovnishverma/free-qr-code-generator.io )에 코드 목록을 붙여넣어 QR 이미지들을 만들고 인쇄하세요.
- 이 단계는 관리자가 미리 준비하는 과정이라 인터넷 사용에 문제 없습니다. (오프라인이 필요한 건 실제 검증 시점입니다.)

### 3. 검증 (사용처, 스마트폰)
1. `verify.html` 파일을 스마트폰에 저장 (카카오톡/메일로 전송 후 다운로드)해두고, 필요할 때 파일 앱에서 열어 브라우저로 실행합니다.
2. 손님이 제시한 QR코드를 폰 기본 카메라 앱으로 스캔 → 인식된 텍스트를 복사.
3. `verify.html`에 비밀키와 코드를 입력하고 [확인하기] 클릭.
4. 화면에 다음 중 하나가 표시됩니다:
   - ✅ **정상** — 서명이 일치하고 유효기간 이내
   - ⏰ **만료** — 서명은 정상이지만 유효기간이 지남
   - ❌ **위조/오류** — 서명이 일치하지 않음 (발급되지 않은 코드)
   - ⚠️ **이미 사용됨** — 같은 기기에서 이전에 "사용 처리"한 코드

## 코드 형식
```
일련번호-금액-만료일(YYYYMMDD)-서명
예: A1B2C9-10000-20261231-3F9A2C1B4E5D
```
서명은 `HMAC-SHA256(비밀키, "일련번호|금액|만료일")`의 앞 12자리(hex)입니다.

## GitHub 연동 (사용 여부를 여러 기기가 공유)

기본 상태(GitHub 미설정)에서는 "사용 처리"가 그 스마트폰 안에만 기록됩니다. 여러 검증 기기가 사용 여부를
공유하게 하려면 `vouchers.json`을 GitHub 저장소에 두고 API로 읽고/고치도록 연동할 수 있습니다.

### 설정 방법
1. 이 저장소(vouchers.json 포함)를 GitHub에 올립니다.
2. **Fine-grained PAT** 발급: https://github.com/settings/personal-access-tokens/new
   - Repository access: **이 저장소만 선택** (다른 저장소는 절대 포함하지 마세요)
   - Permissions: **Contents → Read and write** 만 부여 (그 외 전부 No access)
3. `issue.html`을 열어 상단 "GitHub 연동 설정"에 owner/repo/branch/token 입력 → [설정 저장]
4. 코드 발급 후 [GitHub에 발급 기록 저장] 클릭 → `vouchers.json`에 발급 목록이 커밋됨
5. 각 검증 기기의 `verify.html`에서도 같은 owner/repo/token을 한 번 입력해두면, 이후 자동으로 GitHub을
   조회해서 "이미 사용됨" 여부를 판단하고, [사용 처리]도 GitHub에 바로 반영합니다.

### 동작 방식
- 서명(위조) 검증 자체는 여전히 완전 오프라인입니다.
- "사용 여부"만 GitHub을 조회하므로, **그 순간엔 인터넷 연결이 필요**합니다.
- 네트워크가 안 되거나 GitHub 설정을 안 했다면, 자동으로 "오프라인 모드"(이 기기 로컬 기록)로 대체 동작합니다.
- 두 기기가 거의 동시에 같은 코드를 사용 처리하면, 나중 요청은 "다른 기기에서 방금 먼저 사용 처리했습니다" 오류로 안전하게 막힙니다 (GitHub 파일의 sha 값으로 충돌 감지).

## 알아둘 점 (한계)
- **비밀키가 곧 보안의 전부입니다.** 비밀키를 아는 사람은 코드를 위조할 수 있으므로, 검증 담당자에게만 구두/별도 채널로 전달하세요. (verify.html 파일 자체에는 비밀키가 들어있지 않습니다 — 매번 입력해야 합니다.)
- **GitHub 토큰은 브라우저에 노출됩니다.** 개발자도구로 페이지를 열면 누구나 토큰을 볼 수 있어, 이론적으로는 `vouchers.json`을 마음대로 고칠 수 있습니다. 그래서 반드시 **이 저장소 하나에만, Contents 권한만** 준 Fine-grained PAT를 쓰세요 — 유출되어도 피해 범위가 이 장난감 저장소로 한정됩니다. 진짜 보안이 필요한 용도라면 토큰을 서버(예: Cloudflare Worker)에 숨기는 구조로 바꿔야 합니다.
- GitHub 연동 없이 로컬 모드로만 쓰는 경우, "중복 사용 방지"는 기기별로만 동작합니다 (기존 한계와 동일).
- 더 강한 보안(키 유출 시에도 위조 방지)이 필요하면 HMAC 대신 비대칭 서명(Ed25519 등)으로 바꿀 수 있습니다 — 필요하면 요청하세요.
