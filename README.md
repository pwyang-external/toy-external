# 사내 상품권 QR 발급/검증 도구

서버·앱 없이, 서명(HMAC-SHA256) 기반으로 상품권 QR코드의 진위를 오프라인으로 확인하는 도구입니다.

## 구성
- `issue.html` — 상품권 코드 발급 + QR 이미지 생성 (관리자가 PC에서 1회 실행)
- `verify.html` — 상품권 진위 확인 (검증자가 스마트폰에서 사용)
- `github-sync.js` — GitHub API로 `vouchers.json`을 읽고/쓰는 공통 로직
- `qrcode-lib.js` — QR 이미지 생성 라이브러리 (타사 오픈소스, 아래 "third-party" 참고)
- `github-config.local.example.js` — GitHub 설정 템플릿 (커밋됨, 토큰 없음)
- `github-config.local.js` — 실제 GitHub 설정/토큰, 평문 (⚠️ `.gitignore`에 등록되어 커밋되지 않음, 이 파일이 있는 그 컴퓨터에서만 동작)
- `crypto-config.js` — 설정을 암호(패스프레이즈)로 암호화/복호화하는 공통 로직
- `make-config.html` — 관리자가 최초 1회 실행해 `github-config.encrypted.json`을 만드는 도구
- `github-config.encrypted.json` — 암호화된 GitHub 설정 (커밋해도 안전, 어느 기기에서든 암호만 알면 사용 가능)

## 사용 절차

### 1. 발급 (관리자, PC)
1. `issue.html`을 더블클릭해서 브라우저로 엽니다 (인터넷 불필요, QR 생성까지 전부 로컬에서 처리).
2. 비밀키 · 금액 · 유효기간 · 발급 수량을 입력하고 [코드 발급하기] 클릭 → 코드마다 QR 이미지가 바로 표에 나타납니다.
3. 다음 중 편한 방식으로 QR 이미지를 확보합니다:
   - 표의 각 행 [PNG 저장] 링크로 하나씩 다운로드
   - [🖨️ 전체 QR 인쇄용 시트 열기] — 모든 QR을 카드 형태로 모아 인쇄(또는 PDF로 저장) 미리보기가 새 창으로 뜸
4. **비밀키는 절대 이 파일에 저장되지 않습니다.** 별도의 안전한 곳(비밀번호 관리자 등)에 기록해두세요. 이 값을 잃으면 검증이 불가능합니다.

### 2. 검증 (사용처, 스마트폰)
1. `verify.html` 파일을 스마트폰에 저장 (카카오톡/메일로 전송 후 다운로드)해두고, 필요할 때 파일 앱에서 열어 브라우저로 실행합니다.
2. 손님이 제시한 QR코드를 폰 기본 카메라 앱으로 스캔 → 인식된 텍스트를 복사.
3. `verify.html`에 비밀키와 코드를 입력하고 [확인하기] 클릭.
4. 화면에 다음 중 하나가 표시됩니다:
   - ✅ **정상** — 서명이 일치하고 유효기간 이내
   - ⏰ **만료** — 서명은 정상이지만 유효기간이 지남
   - ❌ **위조/오류** — 서명이 일치하지 않음 (발급되지 않은 코드)
   - ⚠️ **이미 사용됨** — 같은 기기에서 이전에 "사용 처리"한 코드

## 코드 형식
```
일련번호-금액-만료일(YYYYMMDD)-서명
예: A1B2C9-10000-20261231-3F9A2C1B4E5D
```
서명은 `HMAC-SHA256(비밀키, "일련번호|금액|만료일")`의 앞 12자리(hex)입니다.

## GitHub 연동 (사용 여부를 여러 기기가 공유)

기본 상태(GitHub 미설정)에서는 "사용 처리"가 그 스마트폰 안에만 기록됩니다. 여러 검증 기기가 사용 여부를
공유하게 하려면 `vouchers.json`을 GitHub 저장소에 두고 API로 읽고/고치도록 연동할 수 있습니다.

### 설정 방법
1. 이 저장소(vouchers.json 포함)를 GitHub에 올립니다.
2. **Fine-grained PAT** 발급: https://github.com/settings/personal-access-tokens/new
   - Repository access: **이 저장소만 선택** (다른 저장소는 절대 포함하지 마세요)
   - Permissions: **Contents → Read and write** 만 부여 (그 외 전부 No access)
3. `make-config.html`을 열어 owner/repo/branch/path/token과 **암호(패스프레이즈)**를 입력하고 생성 버튼 클릭
   → `github-config.encrypted.json` 다운로드됨. 이 파일을 `issue.html`/`verify.html`과 같은 폴더에 두고
   **git에 커밋해도 됩니다** (암호 없이는 내용을 알 수 없어 안전합니다).
4. **이때 정하는 암호를, 상품권 발급용 "비밀키"와 똑같이 맞추세요.** 그러면 다음 단계에서 입력값이 하나로 통일됩니다.

### issue.html / verify.html 둘 다 — 입력값은 "비밀키" 하나뿐
`issue.html`에서 [비밀키]를 입력하고 [코드 발급하기]를 누르는 순간, `verify.html`에서 [비밀키]를 입력하고
[확인하기]를 누르는 순간, 그 값으로 다음 두 가지가 동시에 처리됩니다:
1. 상품권 서명(위조) 검증 / 발급
2. `github-config.encrypted.json` 복호화 (성공하면 그 브라우저에 자동 캐시되어 이후엔 다시 시도 안 함)

GitHub owner/repo/token 같은 건 화면에서 따로 볼 일도, 입력할 일도 없이 **비밀키 하나만** 다루면 됩니다.
(암호가 서로 다르면 GitHub 연동만 조용히 실패하고, 서명 검증/발급 자체는 정상 진행됩니다 — "오프라인 모드"로 표시됨.
GitHub 설정을 굳이 따로 넣고 싶다면 각 파일의 "⚙️ GitHub 연동 수동 설정"을 펼쳐서 직접 입력할 수도 있습니다.)

발급 후 [GitHub에 발급 기록 저장]을 클릭하면 `vouchers.json`에 발급 목록이 커밋되고, 각 검증 기기는
자동으로 GitHub을 조회해서 "이미 사용됨" 여부를 판단하고 [사용 처리]도 GitHub에 바로 반영합니다.

> 참고: `issue.html`은 관리자 PC 한 대에서만 쓴다면, `github-config.local.example.js`를 복사한
> `github-config.local.js`(평문, `.gitignore`로 커밋 차단됨)에 값을 직접 넣어두는 방법도 여전히 됩니다.
> 이 경우 비밀키 입력 없이도 항상 자동으로 채워집니다 — 단, 그 컴퓨터에서만 동작합니다.

### QR을 찍으면 검증 페이지로 바로 연결하기 (선택)
`issue.html`에서 코드를 발급할 때 **"검증 페이지 URL"**란에 배포된 `verify.html`의 주소
(예: `https://junyoungkim.github.io/voucher-qr/verify.html`)를 입력해두면, QR에는 코드 텍스트 대신
`그URL?code=코드` 형태의 링크가 담깁니다.

효과:
- 손님/검증자가 QR을 스마트폰 **카메라로 찍으면 바로 verify.html이 열리고, 코드 입력창이 자동으로 채워집니다** (직접 복사/붙여넣기 불필요).
- 검증자가 [비밀키]를 한 번 입력해 [확인하기]를 누르면, 그 비밀키가 이 기기에 기억되어 **다음 QR부터는 스캔하자마자 결과까지 자동으로 뜹니다** (코드+비밀키가 둘 다 채워지면 자동 실행).
- "이 기기에 저장된 비밀키 지우기" 버튼으로 언제든 이 캐시를 지울 수 있습니다.

이 URL 입력란은 이 컴퓨터의 localStorage에 저장되어 다음 발급 때도 자동으로 채워집니다.

### 동작 방식
- 서명(위조) 검증 자체는 여전히 완전 오프라인입니다.
- "사용 여부"만 GitHub을 조회하므로, **그 순간엔 인터넷 연결이 필요**합니다.
- 네트워크가 안 되거나 GitHub 설정을 안 했다면, 자동으로 "오프라인 모드"(이 기기 로컬 기록)로 대체 동작합니다.
- 두 기기가 거의 동시에 같은 코드를 사용 처리하면, 나중 요청은 "다른 기기에서 방금 먼저 사용 처리했습니다" 오류로 안전하게 막힙니다 (GitHub 파일의 sha 값으로 충돌 감지).

## 알아둘 점 (한계)
- **비밀키가 곧 보안의 전부입니다.** 비밀키를 아는 사람은 코드를 위조할 수 있으므로, 검증 담당자에게만 구두/별도 채널로 전달하세요. (verify.html 파일 자체에는 비밀키가 들어있지 않습니다 — 매번 입력해야 합니다.)
- **암호화된 파일을 쓰더라도, 암호를 입력해서 복호화한 순간엔 토큰이 그 브라우저 메모리에 평문으로 존재합니다.** 즉 암호화는 "git 저장소에 평문으로 남는 것"만 막아줄 뿐, 그 암호를 아는 사람이 실제로 페이지를 열어 복호화하면 이후엔 원래 토큰과 동일한 노출 위험이 생깁니다. 암호는 토큰만큼 중요하게 취급하세요.
- **GitHub 토큰은 브라우저에 노출됩니다.** 개발자도구로 페이지를 열면 누구나 토큰을 볼 수 있어, 이론적으로는 `vouchers.json`을 마음대로 고칠 수 있습니다. 그래서 반드시 **이 저장소 하나에만, Contents 권한만** 준 Fine-grained PAT를 쓰세요 — 유출되어도 피해 범위가 이 장난감 저장소로 한정됩니다. 진짜 보안이 필요한 용도라면 토큰을 서버(예: Cloudflare Worker)에 숨기는 구조로 바꿔야 합니다.
- GitHub 연동 없이 로컬 모드로만 쓰는 경우, "중복 사용 방지"는 기기별로만 동작합니다 (기존 한계와 동일).
- **verify.html은 한 번 입력한 비밀키를 그 기기의 localStorage에 기억해서 다음부터 자동으로 채웁니다.** 검증 기기를 잃어버리거나 다른 사람과 공유한다면 "이 기기에 저장된 비밀키 지우기"로 반드시 삭제하세요.
- 더 강한 보안(키 유출 시에도 위조 방지)이 필요하면 HMAC 대신 비대칭 서명(Ed25519 등)으로 바꿀 수 있습니다 — 필요하면 요청하세요.
